# 项目宣传助手

`project-promotion` 是个人私有工作区：项目事实素材 → 多素材选题 → 各渠道文案版本 → 人工发布 → 反馈复盘。
账号之间隔离，组织管理员不能读取其他用户的记录、生成结果或 Run 事件。

## 使用流程

1. 填写项目绝对路径，让 AI 识别项目全貌、探索源码和文档并生成素材；也可新建素材或粘贴已有资料。支持记录截图、视频、网盘与资料的 HTTP(S) 链接和说明，链接不会自动抓取。
2. 选择素材类型：支持项目概览、应用概览、定位、人群、场景、功能、流程、技术、交付与演进等 21 类（见下表）。一般素材确认需要摘要和事实资料；使用案例需要目标用户、问题、方案与已实现能力。补充说明和实际产出可选，不要求源码依据。演示案例与真实客户案例分开，未来扩展另列。
3. 选择 1–20 份已确认素材，手动或 AI 策划选题；每个选题注明实际引用的素材、目标读者、介绍角度、核心观点与内容结构。编辑确认后分别准备公众号、小红书、抖音、朋友圈任务。
4. 生成结果先进入生成记录，加入草稿后才成为可编辑版本。保存新版本不会覆盖旧版本，确认一个版本后再登记发布时间和链接。
5. 手动登记各作品最新累计指标和匿名咨询问题；未知数据留空，未知来源不关联作品。复盘采用每条作品观察日期最新的记录，不把多次累计数相加，不推断来源或跨平台排名。

品牌资料沿用品牌资料库的私有选择器、权限校验和来源快照，仅带入明确选择的产品与范文。
所有 AI 生成调用统一 Run 与系统模型引擎，失败不改变已保存记录。模型结果仍需人工核实，提示约束与来源快照不构成自动事实核验。
模型服务繁忙时会在同一任务内自动重试两次，等待期间仍可取消；不会切换模型或重复创建素材。
繁忙、认证、额度、超时、JSON 格式与素材字段校验错误分别提示，任务保留错误分类供排查。

## 从项目路径生成素材

在素材库填写**后端和执行 worker 所在机器**上的项目绝对路径，默认使用「全面概览」：覆盖项目主要模块、能力、适用对象和核心流程，按领域归纳，概要介绍。介绍侧重不缩小覆盖范围，不逐项追踪调用链或参数细节。概览列出主要模块覆盖清单、依据类型、资料缺口和后续值得展开的方向。
选择「指定方向深挖」时必须填写模块、功能或主题，仅追踪该方向和必要依赖的实现、步骤及限制。带项目路径的素材卡片可点击「深入此方向」预填表单，核对后提交；既有素材只作定位线索，重新核对当前源码。旧请求未传模式时采用全面概览。

全面概览与深挖分别使用 `PROJECT_PROMOTION_OVERVIEW_TIMEOUT_SECONDS`（默认 600 秒）和 `PROJECT_PROMOTION_DEEP_TIMEOUT_SECONDS`（默认 1200 秒）。这是安全时限，不是目标运行时间；主要通过减少默认模式的读取深度和模型往返来避免无必要的长时间探索，不承诺固定完成时长。普通文案生成仍使用原 `APPLICATION_GENERATION_TIMEOUT_SECONDS`。修改配置后需重启后端与执行 worker。

当前支持有提交记录的 Git 工作区，读取时包含未提交修改与未忽略的新文件。服务运行环境的 PATH 需要包含 Git。
普通用户只能读取自己的工作区；平台管理员遵循系统已有路径策略，不因本应用扩大读取范围。

复用对话应用的 AgentEngine，在一个持续的 Agent 会话内自主使用原生命令工具搜索、批量读文件并整理素材。
后端不再循环调用模型请求 list/search/read/finish JSON，也不按每轮 80 行给 AI 分配资料。
沿用源码读取器创建过滤后的临时快照：Git 忽略文件、凭据文件、依赖目录、二进制、符号链接等被排除，沿用文件数量和文本容量限制。
Agent 的工作目录是此快照，使用受限只读沙箱，禁止写入和沙箱命令联网；本任务关闭外部 MCP、应用连接器和网页搜索。
目前需要系统 Codex app-server 引擎及支持命名 permissions profile 的版本；启动时核对服务端已激活本次只读权限配置。不支持时明确失败，不退回原来的逐轮探索或放宽权限。
Windows 执行账号需要可用的 elevated 沙箱；若出现 `sandbox_unavailable`（例如 `CryptUnprotectData` 凭据解密失败），需在执行账号下修复或重新初始化 Codex 沙箱。应用不会自动改用完全访问权限。
部分 Windows elevated 沙箱要求全盘读取；默认保持目录隔离并提示 `sandbox_read_scope_unsupported`。部署管理员明确授权后，可设置 `PROJECT_PROMOTION_ALLOW_FULL_DISK_READ=True`：AI 仍在过滤后的项目快照中工作，但命令在操作系统权限上可以读取快照外文件。此模式仍禁止写入、网络和外部工具，不会自动启用。
源码和文档会传入系统配置的模型。生成记录展示当前阶段，探索期间可以取消；失败或取消不修改已有素材。
生成记录中的「Agent 执行过程」每 3 秒自动刷新，展示会话启动、搜索/读取命令、执行状态、素材提交及 Agent 对外说明。活动任务默认展开，长记录默认显示最近 8 条，可展开查看；最多保留最近 100 条，省略数量明确提示。完成、失败、取消后仍保留记录，仅本人可访问。命令与说明限长并遮蔽常见凭据字段，不记录原始命令输出或内部推理。
AI 阅读项目后直接通过素材提交工具提交结果，不登记引用编号、行号或代码摘录；字段校验失败时在同一会话内自行修正。

结果为 1–12 份不同事实主题的待审核素材（素材数量上限不限制主要模块清单，模块多时按领域归组），根据实际资料选择类型，不强制填满数量或类型；分析说明项目全貌、覆盖情况和资料缺口。只保留项目来源、读取概况和探索模式，用于后续指定方向继续探索，不收集文件引用与代码摘录。
“加入可编辑草稿”一次保存整组素材，重复点击不会重复创建。历史记录中的源码引用仍保存在原快照中，但不展示，也不传入后续选题、文案和创作交接；版本页面只展示关联素材名称和修订号。
只有文档声明的内容标为设计说明或规划，不能表述为已经实现；开发动机、版本变化和成果样本应来自实际资料，不能从功能代码臆测。
静态阅读不证明功能已部署、实测有效或收益成立，不会伪造截图、客户评价或效果数字。

## 素材分类与探索侧重

项目概览与应用概览分开：例如「创作平台整体介绍」属于项目概览，「项目宣传助手介绍」属于应用概览，「宣传助手的素材筛选」属于功能资料。项目路径是读取范围，不代表每份素材都在介绍整个项目。后续选题也分别使用「项目介绍」与「应用介绍」，不将应用范围扩大为项目范围。已有素材不会自动改类，可在编辑时人工核对调整。

分类是按项目介绍常见问题预设的资料整理维度，AI 根据读到的实际资料选择最贴近的类型，并非从目录自动推导分类，也不代表每个项目都有全部类型。分类描述事实内容，选题再决定目标读者、观点和表达角度；同一事实不因换分类而重复生成。

探索侧重提供两组选择：原有的综合介绍、用户功能与流程、技术实现与设计、业务定位与交付条件，以及以下全部 21 类素材。选择具体分类时，Agent 仅输出该类素材，提交工具和服务端校验会拒绝混入的其他分类；项目全貌可写入分析，但不额外生成概览素材。资料不足会说明缺口，不用其他分类替代，也不将无关内容改标签充数。综合视角仍允许多种分类。全面概览仍覆盖主要模块并保持简洁；深挖仍需填写具体方向，仅展开该方向及必要依赖。12 份输出上限不意味着必须覆盖 21 类。新分类同时用于手动编辑、素材筛选与生成结果校验，不要求源码引用。

| 类型键 | 分类 | 内容范围 |
| --- | --- | --- |
| `overview` | 项目概览 | 整个项目的定位、应用或模块构成、协作关系与整体能力，至多一份 |
| `application_overview` | 应用概览 | 项目内一个具体应用的用途、用户、功能和输入输出，标题明确应用名称 |
| `positioning` | 项目定位 | 解决的核心问题、价值主张与定位；不编造竞品优劣 |
| `audience` | 适用人群 | 适合的用户、角色及使用前提，不虚构已有客户 |
| `scenario` | 应用场景 | 适用的业务情境与任务；设想场景要标注，不冒充真实案例 |
| `feature` | 功能资料 | 单项功能做什么、输入输出及能力范围 |
| `workflow` | 工作流程 | 多个步骤或功能怎样协作完成任务 |
| `case` | 使用案例 | 具体问题、解决过程和结果；演示与真实客户案例分开 |
| `artifact` | 成果样本 | 项目实际产出的内容或文件样本，不编造产物或效果 |
| `quickstart` | 快速上手 | 首次使用的准备条件与最短操作路径，只整理操作事实 |
| `integration` | 集成对接 | 与外部工具、接口和数据的连接方式及条件 |
| `customization` | 定制扩展 | 现有配置、插件和二次开发能力；未实现扩展另列 |
| `architecture` | 技术实现 | 模块职责、关键设计与技术协作方式 |
| `deployment` | 部署运维 | 运行环境、部署方式、维护和故障处理条件 |
| `security` | 安全隐私 | 权限、数据处理与隐私机制；不把机制等同安全认证或合规结论 |
| `performance` | 性能容量 | 已有性能与容量资料；区分设计目标和实测，缺少数据时不编造指标 |
| `boundaries` | 使用边界 | 已知限制、不支持的情况及适用前提 |
| `cost` | 成本资源 | 所需软硬件、外部服务与资源消耗；未知费用留空，不臆测价格 |
| `release` | 版本变更 | 有变更记录的新增、调整与修复 |
| `development` | 开发记录 | 已有开发过程、决策和经验记录，不臆测作者动机 |
| `roadmap` | 未来规划 | 已有计划、TODO 或规划声明，明确尚未实现，不承诺交付日期 |

## 与已有创作应用交接

版本编辑器可以把固定版本带入用户可运行的图文、短视频、公众号写作或公众号排版应用。
目标表单草稿保存在服务器，用户核对参数后使用原应用的 Skill 和对话流程。创建的会话与交接记录关联。
从交接记录选择已成功完成的助手回复回存为新版本；不会更换已确认发布版本。普通创作回复回存到正文，用户可拆分到逐页文案或脚本字段。
排版回复包含 HTML 正文或 HTML 代码块时支持回存；仅提供文件链接时，在版本编辑器粘贴实际 HTML 内容。
HTML 仅作为文本编辑和下载，应用不直接渲染。创作应用的 Skill 与执行环境需按各自文档配置。

## 接口与数据

前缀：`/api/v1/organizations/{organization_id}/applications/{application_id}/project-promotion`。
单租户沿用平台提供的无组织前缀别名。

- `GET/POST /cases|topics|channels|feedback`；`GET/PATCH /{resource}/{uuid}`。列表每页 50 条，用 `page` 分页；PATCH 必须带当前 `revision`，冲突返回 409。归档可恢复。
- `GET/POST /channels/{uuid}/versions`；`POST .../versions/{version_id}/confirm`；`GET .../versions/{version_id}/download?format=md|html`。版本只增不改，确认和发布校验来源版本。
- `GET /report`。按关联素材、渠道返回总数、有效样本数和缺失状态，不自动排名。
- `GET/POST /ai/tasks`；`GET /ai/tasks/{uuid}`；`POST /ai/tasks/{uuid}/apply|cancel`。提交包含最长 160 字符的 `request_key`，同键同载荷返回原任务，同键不同载荷返回 409。应用草稿操作幂等。项目探索使用 `kind=project`、`project_path`、可选 `exploration_mode=overview|deep`、`exploration_focus`（综合视角 `all|user|technical|business` 或下表任一素材类型键） 和 `instruction`（深挖模式必填），返回 `stage` 进度；案例的 `source_snapshot` 只读。
- `GET /integrations`；`GET/POST /handoffs`；`GET/PATCH /handoffs/{uuid}`；`GET/POST /handoffs/{uuid}/results`。回存只接受本人、同组织、关联目标会话中的成功助手回复。

存储与接口继续使用 `Case` / `/cases`，用于兼容已有案例；新增 `data.material_type`（默认 `case`）、`summary` 与 `facts`。原 `category` 三种分类继续接受，新素材默认 `general`。
选题新增 `case_ids`（1–20 个素材 UUID），`case_id` 保留为第一份素材的兼容字段；同时传入时必须一致。旧客户端只传原 `case_id` 更新不会丢弃其他关联素材。选题可编辑来源，每次修改增加 revision。
选题任务 `topics` / `review` 接受 `case_ids` 或旧 `case_id`。新多素材生成结果逐题声明实际使用的 `case_ids`；只允许输入中存在的素材，单素材旧结果可省略。加入草稿时检查来源确认状态与修订号。
选题角度扩展为项目介绍、适用人群、功能演示、问题解决、完整流程、成果展示、对比取舍、上手技巧、技术解读、使用边界、开发演进、实践复盘；按资料策划，不再每种方向固定生成一条。`data.thesis` 和 `data.outline` 保存观点和结构。
文案快照同时保存 `cases` 全部来源及旧 `case` 主来源。生成、确认、发布检查所有来源；旧单案例版本仍可核对。创作交接继承完整版本快照。复盘按实际发布版本的来源归组，多素材作品可进入多个素材组，组间不能相加或推断单素材贡献。

表为 Case、Topic、TopicMaterial、Channel、Version、Feedback、AITask、Workspace、Handoff，全部组织隔离，PostgreSQL 增加 RLS。迁移 `0004` 添加多素材关联表，不改写历史私有记录；没有关联表记录的历史选题沿用原 case 外键。
没有导入旧应用数据，也不预填未经验证的案例或收益数字。

## 安装与验证

从仓库根目录使用项目虚拟环境：

```powershell
backend\venv\Scripts\python.exe backend\manage.py validate_app_center
backend\venv\Scripts\python.exe backend\manage.py migrate project_promotion --noinput
backend\venv\Scripts\python.exe backend\manage.py sync_app_center --package project-promotion
```

当前 macOS 工作区从仓库根目录使用 `backend/.venv/bin/python`：

```bash
backend/.venv/bin/python backend/manage.py migrate project_promotion --noinput
backend/.venv/bin/python backend/manage.py sync_app_center --package project-promotion
```

部署本次更新时先执行 `migrate project_promotion`，再重启后端与执行 worker 以载入应用；前端更新后在应用中心打开「项目宣传助手」。

后端测试：在 backend 目录执行 `venv\Scripts\python.exe -m pytest app_center/project_promotion/backend/tests -q`。
前端测试覆盖 `projectPromotion.test.tsx`、`promotionLayout.test.ts`，以及共用交接草稿的 `repoHandoff.test.tsx`。
类型检查、lint、生产构建与静态 CSS 检查不代表真实浏览器或手机视觉验收。
