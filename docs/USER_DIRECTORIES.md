# 用户专属工作目录

用户工作目录按不可变用户 ID 分配：`AGENT_WORKSPACE_ROOT/users/<user_id>/`。
新用户保存时自动创建；已有用户在运行 Django `migrate` 后补建，也可在后端虚拟环境中执行 `python manage.py provision_user_directories`。目录在首次使用时也会自动补齐。重复执行不会覆盖已有文件。

- 普通用户、审计员、仅有 Django `is_staff` 标记的用户，只能浏览、扫描或绑定自己的目录。组织成员关系不授予其他成员的路径访问权限。
- 平台管理员（`role=admin` 或 `is_superuser`）在 `APPLICATION_RUNTIME_ALLOW_ALL_PATHS=True` 时可访问任意路径，仍受后端进程的操作系统权限限制。关闭此开关后，管理员可访问自己的目录和 `APPLICATION_RUNTIME_ALLOWED_ROOTS` 配置的目录。
- 会话、项目、应用和工作流的新工作目录都在用户目录下分配。应用执行器收到的 `allowed_roots` / `allow_all_paths` 由任务所属用户决定，用户提交的任务参数不能覆盖顶层授权值。
- 会话的“完全控制”模式仅允许具备全路径权限的管理员使用，执行器也会拒绝普通用户遗留任务中的该模式。
- 路径在权限判断前会展开、规范化并解析软链接。目录列表不会暴露指向授权范围外的软链接，也不会返回用户根目录的父路径。
- 创作大师的浏览接口及运行时使用统一授权范围；旧的 `CREATION_MASTER_ALLOW_ALL_PATHS` 设置不再授予额外权限。

历史组织共享目录和外部绑定不会自动搬迁、复制或删除。普通用户再次访问范围外的已保存路径会被拒绝；管理员需要确认文件归属后将其迁入对应用户目录，并更新绑定。旧的共享 `organizations/<id>/system` 默认目录会切换到新的独立会话目录，不复制未确定归属的共享文件。

这是应用层文件接口和工作目录授权，不是操作系统级沙箱。后端进程、插件代码、远程主机以及执行任意命令的智能体工具仍需各自的执行隔离，不能把目录校验当成对任意代码执行的安全隔离。
