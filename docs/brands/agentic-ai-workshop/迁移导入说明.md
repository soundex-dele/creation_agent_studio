# 品牌资料库迁移导入

此导入包包含「智能体AI工坊」品牌档案和 Agent Studio 产品资料。脚本使用目标项目的数据库配置和应用校验规则，不依赖原机器的用户 ID、组织 ID、应用 ID 或资料 UUID。

## 要一起迁移的文件

- 项目代码（包含新命令及 `backend/scripts/import_brand_library.py`）。
- 本目录的 `import-manifest.json`、`brand-profile.json`、`product-agent-studio.json`。
- 后续若增加范文或产品，还需携带清单中引用的对应 JSON 文件。

`import-receipt.json` 是上次导入记录，不作为导入数据。Markdown 内容手册、台账及创作上下文继续作为本地参考文档，不会被塞进优秀范文模块。

**导入读取 JSON 文件快照。** 以后只在应用界面修改的资料不会自动回写本目录；迁移前应把最新资料同步到这些 JSON 文件，或完整迁移应用数据库。

## 准备目标环境

先完成项目依赖安装和数据库配置，创建目标账号及组织成员关系，并安装品牌资料库应用。脚本不创建账号、不修改权限、不自动执行数据库迁移。

以下命令均从仓库根目录执行，使用项目虚拟环境。目标环境的 `DJANGO_SETTINGS_MODULE`、数据库环境变量或 `.env` 应与实际服务一致。

macOS / Linux：

```bash
backend/.venv/bin/python backend/manage.py migrate --noinput
backend/.venv/bin/python backend/manage.py sync_app_center --package brand-library --organization <目标组织UUID>
```

Windows PowerShell：

```powershell
backend\venv\Scripts\python.exe backend\manage.py migrate --noinput
backend\venv\Scripts\python.exe backend\manage.py sync_app_center --package brand-library --organization <目标组织UUID>
```

将占位符替换为真实 UUID。应用同步命令要求 UUID；下面的品牌导入命令还支持组织 slug。正式环境请保留服务原有 settings 配置；没有显式设置时，脚本与 `manage.py` 一样默认使用开发配置。

## 预览并导入

`admin` 是本次使用的账号，可替换成目标用户名。账号只有一个有效组织成员关系时，`--organization` 可省略；有多个时必须传组织 UUID 或 slug，避免选错。

macOS / Linux：

```bash
# 只读预览：显示目标组织、应用及每项 create / update / skip
backend/.venv/bin/python backend/scripts/import_brand_library.py --username admin --dry-run

# 确认目标配置无误后导入
backend/.venv/bin/python backend/scripts/import_brand_library.py --username admin
```

Windows PowerShell：

```powershell
backend\venv\Scripts\python.exe backend\scripts\import_brand_library.py --username admin --dry-run
backend\venv\Scripts\python.exe backend\scripts\import_brand_library.py --username admin
```

指定组织或导入包：

```bash
backend/.venv/bin/python backend/scripts/import_brand_library.py --username admin --organization <目标组织UUID或slug> --bundle /absolute/path/import-manifest.json
```

也可使用等价 Django 命令：

```bash
backend/.venv/bin/python backend/manage.py import_brand_library --username admin --dry-run
```

脚本不要求从仓库根目录启动；默认导入包按脚本所在项目定位。显式传入的相对 `--bundle` 路径则相对当前工作目录。

## 当前开发机的特定数据库

本次实际应用使用的是 `backend/dev-computer.sqlite3`，与默认的 `db.sqlite3` 不同。在当前机器运行时应明确指定该文件。迁移到其他环境时使用目标服务的配置，不照搬这个本地路径。

```bash
SQLITE_PATH="$PWD/backend/dev-computer.sqlite3" backend/.venv/bin/python backend/scripts/import_brand_library.py --username admin --dry-run
SQLITE_PATH="$PWD/backend/dev-computer.sqlite3" backend/.venv/bin/python backend/scripts/import_brand_library.py --username admin
```

## 重复导入与更新

- 档案按「账号＋组织＋应用＋档案名称」匹配；产品和范文还限定在该档案内，并按名称匹配。
- 没有同名资料：创建新记录，ID 由目标数据库生成。
- 同名且导入字段一致：跳过，保留 ID 和更新时间。
- 同名但内容不同：默认整次停止，任何条目都不写入。`--dry-run` 会在 `conflicts` 中列出差异字段。
- 确实要以文件内容更新时，增加 `--on-conflict update`。未出现在文件中的顶层字段保留；如果提供 `voice` 等模块，则整体替换这个模块。产品 `facts` 列表也整体替换。
- 不会删除目标库里额外的产品、范文或其他品牌；不会读取或修改其他账号的同名档案。
- 目标库或清单内已有多个同名条目时会拒绝导入，需先消除歧义。修改文件里的名称会被视为新条目，不用于给旧记录改名。

```bash
backend/.venv/bin/python backend/scripts/import_brand_library.py --username admin --on-conflict update --dry-run
backend/.venv/bin/python backend/scripts/import_brand_library.py --username admin --on-conflict update
```

一次导入在同一事务中完成，写入或核对失败会回滚本次变化。正式执行成功时输出 JSON，`status` 为 `committed_and_verified`，包含每个条目的 ID 与处理动作。预览输出 `status: preview`，即使列出了 `conflicts` 也不写入。

## 增加产品或范文

清单格式如下；文件路径相对清单所在目录，不能跳出该目录：

```json
{
  "version": 1,
  "profile": "brand-profile.json",
  "products": ["product-agent-studio.json"],
  "examples": []
}
```

增加产品时，按现有产品文件的字段建立新 JSON，并把文件名加到 `products`。增加真实范文时，在 `examples` 中列出新文件名；单条范文示例结构：

```json
{
  "name": "实际文章标题",
  "platform": "公众号",
  "body": "实际正文",
  "source_url": "",
  "highlights": "希望后续创作借鉴的具体写法"
}
```

数据文件只放可编辑字段，不包含 `id`、`owner`、`organization`、`application_id`、时间戳等服务端字段。内容长度和字段名由品牌资料库原有序列化器校验。
